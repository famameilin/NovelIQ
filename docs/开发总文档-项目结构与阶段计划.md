## 一、项目概述

### 范围与原则
- 覆盖：本地模型 + 云端模型双模型协作工作流，围绕七大分析维度的工程落地骨架。
- 原则：先搭框架、再填实现；结构清晰、职责单一、数据流可追踪。

### 双模型架构

| 维度 | 本地小模型 | 云端大模型 |
|------|---------------------------|-------------------------|
| 调用频次 | 高频（每块一次，数百次） | 低频（每部书5-15次） |
| 任务难度 | 结构化提取、局部语义理解 | 跨章节推理、综合判断 |
| 上下文长度 | 单块~2000字 + 滚动摘要 | 全书摘要 + 关键片段 |
| 成本 | 零（本地GPU） | 按token计费，单书<$2 |
| 输出格式 | 严格JSON（Pydantic校验） | 自然语言报告/JSON均可 |

**分工原则**：代码能算的绝不交给模型；模型只输出原始信号字段，最终指标由代码聚合。

**模型调用架构**：
- 使用 **LiteLLM** 统一多提供商调用接口，支持 OpenAI 兼容服务、DeepSeek、Claude、本地模型等
- 使用 **Pydantic** 定义数据模型，提供类型安全和自动验证
- 当前结构化输出运行时使用项目内 `structured_output` 适配层；**Instructor 已从 live runtime 移除**

### ID 体系

系统当前对外与对内同时存在两层任务标识：

| ID 类型 | 格式 | 示例 | 用途 |
|---------|------|------|------|
| novel_id | UUID前8位 | `10960c77` | 小说唯一标识 |
| task_id | 8位短 ID | `a1b2c3d4` | 对外任务标识，前端/API/日志/结果文件使用 |
| run_id | `analysis_runs.run_id` 字段 | `a1b2c3d4` / 历史 UUID | 数据库内部任务字段名，当前新任务通常直接写入 `task_id`，历史数据兼容完整 UUID |

**ID 使用规则：**
- 每次上传小说生成一个 `novel_id`
- 每次启动分析任务生成一个对外 `task_id`
- 一个小说可以有多个分析任务（task_id）
- 数据通过 `analysis_runs.run_id` 字段在数据库中隔离；当前新任务通常令 `run_id == task_id`
- 日志目录命名：`logs/{task_id}/`
- 结果文件命名：`outputs/{task_id}.json`
- 读取侧仍兼容历史完整 UUID `run_id`，但对外契约统一使用 `task_id`

### 输入与输出边界
- 输入：原始小说文本（单文件或目录）、可选元数据（书名、作者、类型）。
- 输出：PostgreSQL 数据库、分析报告（结构化 JSON + 可视化图表数据 + 说明文档）。

## 二、项目结构

### 完整目录结构

```
/src
  /api              # FastAPI Web 服务与任务编排入口
    /routes         # novels / analysis / results / sse / timeline
    /services
      analysis_service.py   # 当前任务主编排入口
      task_manager.py       # 进程级执行缓存（非业务真相源）
      /analysis             # StageExecutor / 环境初始化 / 错误收口
  /chunking         # 分块与语义分块
  /config           # 配置加载、日志、路径
  /context          # 上下文增强与活跃实体检索
  /ingest           # 文本读取与输入适配
  /knowledge        # graph authority / 图谱读取真相层
  /lexicons         # 词表加载与校验
  /metrics          # 指标计算、曲线与聚合
  /models
    /cloud          # 云端诊断与 payload 构造
    /interactions   # 模型交互记录
    /local          # 本地模型、标注、多阶段输出
    /structured_output # provider-native 结构化输出适配层
  /preprocess       # 清洗、分句、tokenize
  /rag              # 检索与证据组装
  /report           # 导出与报告 schema
  /storage          # ORM、Repository、数据库连接
    /models
    /repositories
    id_mapping.py   # task_id / run_id 兼容映射
  /topic            # LDA 主题建模与模型落盘
  /workflows        # preprocess / annotate / aggregate / topic / diagnose
/frontend           # React + Vite 前端（当前可视化主入口）
/tests              # 单元测试与集成测试
/data
  /lexicons         # 各类词表文件
  /uploads          # 上传小说文件
/outputs
  {task_id}.json    # 结果文件
/logs
  novel_qa.log
  {task_id}/        # 任务日志目录
/scripts
  dev.ps1           # 当前统一开发入口
  run_api.py        # API 服务启动脚本
/deprecated
  /cli              # 历史 CLI 代码归档（当前工作树无 live src/cli）
```

## 五、词表建设

### 词表处理原则
- **优先级**：高优先级词表（语义类别、五感、战斗词、专有词典、典故）用于主流程；低优先级词表（儒道佛民间）在主流程稳定后再启用。
- **建设方式**：模型生成候选词 → 人工审核删改 → 定稿；每类 50–150 条为主，优先保证召回率。
- **存放与命名**：置于 /data/lexicons/，一类一文件，命名与指标一致，便于版本管理与加载。
- **校验与回填**：词表只做粗筛，云端模型负责语境校验；运行中记录高频未命中词，按批次补充。
- **迭代原则**：一次迭代只改一个词表，避免跨层调整造成指标波动。

## 七、API文档引用

> 📄 **详细API文档请参阅**: [API文档.md](API文档.md)

### 快速参考

**服务启动：**
```bash
# 方式一：使用模块启动（推荐，带端口占用检测）
python -m src.api.main --host 0.0.0.0 --port 8000

# 方式二：使用启动脚本（带端口占用检测）
python scripts/run_api.py --port 8000

# 开发模式（支持热重载）
python -m src.api.main --reload
# 或
python scripts/run_api.py --reload

# 指定其他端口
python -m src.api.main --port 8001
```

**启动参数说明：**
| 参数 | 默认值 | 说明 |
|------|--------|------|
| --host | 0.0.0.0 | 监听地址 |
| --port | 8000 | 监听端口 |
| --reload | False | 启用开发模式自动重载 |

**端口占用检测：** 使用 `python -m src.api.main` 或 `python scripts/run_api.py` 启动时，会自动检测端口是否被占用，如果被占用会显示友好的错误提示并退出。

**在线文档：**
- Swagger UI: `http://localhost:8000/api/docs`
- ReDoc: `http://localhost:8000/api/redoc`

## 一、项目概述

### 范围与原则
- 覆盖：本地模型 + 云端模型双模型协作工作流，围绕七大分析维度的工程落地骨架。
- 原则：先搭框架、再填实现；结构清晰、职责单一、数据流可追踪。

### 双模型架构

| 维度 | 本地小模型 | 云端大模型 |
|------|---------------------------|-------------------------|
| 调用频次 | 高频（每块一次，数百次） | 低频（每部书5-15次） |
| 任务难度 | 结构化提取、局部语义理解 | 跨章节推理、综合判断 |
| 上下文长度 | 单块~2000字 + 滚动摘要 | 全书摘要 + 关键片段 |
| 成本 | 零（本地GPU） | 按token计费，单书<$2 |
| 输出格式 | 严格JSON（Pydantic校验） | 自然语言报告/JSON均可 |

**分工原则**：代码能算的绝不交给模型；模型只输出原始信号字段，最终指标由代码聚合。

**模型调用架构**：
- 使用 **LiteLLM** 统一 100+ LLM 提供商的调用接口，支持 OpenAI、DeepSeek、Claude、本地模型等
- 使用 **Instructor** 实现基于 Pydantic 的结构化输出，自动验证和重试
- 使用 **Pydantic** 定义数据模型，提供类型安全和自动验证

### ID 体系

系统使用两种 ID 进行标识：

| ID 类型 | 格式 | 示例 | 用途 |
|---------|------|------|------|
| novel_id | UUID前8位 | `10960c77` | 小说唯一标识 |
| run_id | UUID前8位 | `a1b2c3d4` | 分析任务标识 |

**ID 使用规则：**
- 每次上传小说生成一个 `novel_id`
- 每次启动分析任务生成一个 `run_id`
- 一个小说可以有多个分析任务（run_id）
- 数据通过 `run_id` 字段在数据库中隔离
- 日志目录命名：`logs/{run_id}/`
- 结果文件命名：`outputs/{run_id}.json`

### 输入与输出边界
- 输入：原始小说文本（单文件或目录）、可选元数据（书名、作者、类型）。
- 输出：PostgreSQL 数据库、分析报告（结构化 JSON + 可视化图表数据 + 说明文档）。

## 五、词表建设

### 词表处理原则
- **优先级**：高优先级词表（语义类别、五感、战斗词、专有词典、典故）用于主流程；低优先级词表（儒道佛民间）在主流程稳定后再启用。
- **建设方式**：模型生成候选词 → 人工审核删改 → 定稿；每类 50–150 条为主，优先保证召回率。
- **存放与命名**：置于 /data/lexicons/，一类一文件，命名与指标一致，便于版本管理与加载。
- **校验与回填**：词表只做粗筛，云端模型负责语境校验；运行中记录高频未命中词，按批次补充。
- **迭代原则**：一次迭代只改一个词表，避免跨层调整造成指标波动。

python -m src.cli.main --help

python -m src.cli.main preprocess --source <文件或目录> --run-id <运行ID>

# 标注：使用本地模型进行语义标注
python -m src.cli.main annotate --run-id <运行ID> [--resume]

python -m src.cli.main run --source <文件或目录> --run-id <运行ID>

### 输出说明

> 📄 **详细数据库设计文档请参阅**: [数据库设计文档.md](数据库设计文档.md)

数据库包含以下主要表：

#### 核心数据表（7个）
- `chunks`：文本块
- `chunk_style`：语言风格指标（MTLD、TTR、句长等）
- `chunk_annotation`：语义标注（情感、事件类型等）
- `chunk_characters`：人物信息
- `chunk_relations`：人物关系
- `chunk_dialogues`：对话信息
- `chunk_topics`：主题分布

#### 曲线数据表（3个）
- `emotion_curve`：情感曲线
- `rhythm_curve`：节奏曲线
- `chunk_culture`：传统文化密度

#### 实体管理表（6个）
- `entities`：消歧后实体
- `entity_aliases`：实体别名映射
- `entity_relations`：实体关系
- `entity_snapshots`：实体状态快照
- `entity_registry`：活跃实体注册表
- `character_appearances`：角色出现记录

#### 全局数据表（5个）
- `global_stats`：全局统计指标
- `global_context`：全局上下文
- `cloud_analysis`：云端诊断结果
- `token_usage`：Token使用统计
- `graph_storage`：人物关系图存储

#### 辅助数据表（2个）
- `chunk_summaries`：块摘要
- `chunk_embeddings`：块向量嵌入

**共计 23 个数据表**，详细结构请参阅 [数据库设计文档.md](数据库设计文档.md)。

# 动态主题色系统设计

> **版本**: v1.0  
> **创建时间**: 2026-04-02  
> **定位**: 描述「一书一色」动态主题色系统的完整设计，包括种子色来源、HSL 派生算法、CSS 变量体系、深浅模式切换

---

## 一、设计理念

每本小说拥有独特的视觉身份——后端在诊断阶段为每本书生成一个**种子色**（`theme_color`），前端将这个单一十六进制色值转换为 HSL 色彩空间，通过数学运算派生出完整的色板，包括深色模式和浅色模式的所有色彩。

**核心优势**：
- 后端只需返回一个 `#RRGGBB`，前端开销为零（纯 CSS 变量 + 一次性 JS 计算）
- 深浅切换不需要额外接口调用，仅调整 L（亮度）和 S（饱和度）偏移系数
- 切换书籍时只需更新 CSS 变量根节点，所有组件自动联动

## 二、种子色来源

### 2.1 后端返回

诊断阶段（`GET /api/novels/{novel_id}/diagnosis`）在现有响应中新增 `theme_color` 字段：

{

**生成策略建议**（由后端诊断 prompt 引导 LLM 生成）：

| 小说类型/基调 | 建议色相范围 | 示例 |
|--------------|-------------|------|

| 科幻 | 冷青色系 (170°-200°) | `#00B4D8` |

### 2.2 兜底机制

| 场景 | 处理方式 |
|------|---------|
| 分析已完成，有 `theme_color` | 使用后端返回的种子色 |
| 分析未完成 / 无诊断数据 | 保持 neutral palette，不切入任务主题 |
| `theme_color` 格式非法 | 保持 neutral palette；当前实现不会仅因格式非法主动告警 |

## 三、HSL 派生算法

### 3.1 Hex → HSL 转换

```typescript
interface HSL {
  h: number; // 0-360
  s: number; // 0-100
  l: number; // 0-100
}

function hexToHSL(hex: string): HSL {
  const r = parseInt(hex.slice(1, 3), 16) / 255;
  const g = parseInt(hex.slice(3, 5), 16) / 255;
  const b = parseInt(hex.slice(5, 7), 16) / 255;

  const max = Math.max(r, g, b);
  const min = Math.min(r, g, b);
  const d = max - min;

  let h = 0;
  if (d !== 0) {
    if (max === r) h = ((g - b) / d) % 6;
    else if (max === g) h = (b - r) / d + 2;
    else h = (r - g) / d + 4;
    h = Math.round(h * 60);
    if (h < 0) h += 360;
  }

  const l = (max + min) / 2;
  const s = d === 0 ? 0 : d / (1 - Math.abs(2 * l - 1));

  return {
    h,
    s: Math.round(s * 100),
    l: Math.round(l * 100),
  };
}
```

### 3.2 色板派生规则

当前实现仍是“Hex → HSL → light/dark palette”大方向，但**不应再把下面的值当作精确公式**。

live helper 的关键规则是：

- 基础变量使用 `--primary`、`--background`、`--surface`、`--text`、`--chart-*`
- 浅色背景不再逼近纯白，而是保留 seed hue 的可见色调
- 背景/边框/文字会根据 seed 饱和度动态计算
- 首页与 neutral route 走独立的 `generateHomeThemePalette()`

可以把当前派生口径概括为：

```text
light:
  --primary / --primary-hover / --primary-active
  --background / --surface / --surface-hover
  --border / --border-subtle
  --text / --text-secondary / --text-muted
  --chart-1 ~ --chart-5 / --chart-positive / --chart-negative / --chart-neutral

dark:
  同一套变量名，但亮度、饱和度与对比度按 dark mode 重新推导
```

### 3.3 图表配色补充说明

- **情绪/正负极性**相关的颜色（正面绿、负面红）使用**固定色值**，不跟随主题色，确保语义一致性
- **数据系列色**通过在种子色色相 H 上偏移 ±40°、±80° 生成，保证色彩和谐且可区分
- 深色模式下图表色的 L 值需 +10%，确保在暗色背景上有足够对比度

### 3.4 对比度安全校验

```typescript
/**
 * 计算两个 HSL 颜色之间的 WCAG 对比度
 * 要求：文字与背景的对比度 ≥ 4.5:1（AA级）
 * 如果不达标，自动调整文字色的 L 值
 */
function ensureContrast(foreground: HSL, background: HSL): HSL {
  const fgLum = relativeLuminance(hslToRgb(foreground));
  const bgLum = relativeLuminance(hslToRgb(background));
  const ratio = contrastRatio(fgLum, bgLum);

  if (ratio >= 4.5) return foreground;

  // 背景偏亮 → 文字加深，背景偏暗 → 文字提亮
  const adjusted = { ...foreground };
  if (bgLum > 0.5) {
    adjusted.l = Math.max(adjusted.l - 10, 5);
  } else {
    adjusted.l = Math.min(adjusted.l + 10, 95);
  }
  return adjusted;
}
```

## 四、CSS 变量体系

### 4.1 全局 CSS 入口

当前 live 实现分为两层：

1. **基础变量层**：`--primary`、`--background`、`--text`、`--chart-*`
2. **Tailwind 暴露层**：通过 `globals.css` 的 `@theme inline` 将基础变量映射到 `--color-*`

也就是说，JS hook 当前写入的是基础变量层，而不是直接写 `--color-primary` 这一层。

关键事实：

- `useNovelTheme()` / `generateThemePalette()` 写入：`--primary`、`--background`、`--surface`、`--text` 等
- Tailwind 组件消费：`bg-primary`、`text-text` 等别名
- 首页 / 中性态还会走独立的 `generateHomeThemePalette()`

### 4.2 TailwindCSS 配置

当前仓库使用 **TailwindCSS v4 + `@theme inline`**，并没有 `tailwind.config.ts` 这层颜色映射文件。

## 五、前端实现

### 5.1 主题生成函数

当前 live helper：

- `generateThemePalette(seedHex)`：生成任务主题色板
- `generateHomeThemePalette()`：首页 / neutral route 专用色板

当前公式与早期文档不同点：

- 浅色背景不再逼近纯白，而是让 seed hue 在背景上肉眼可见
- 公式会基于 seed 饱和度动态计算 `softSurfaceS / softBorderS / textS`
- 首页与未选 task 场景不再复用业务页 palette，而是使用独立中性品牌色板

### 5.2 Zustand 主题 Store

当前 store 不再只是：

- `seedColor`
- `isDark`

live store 还包含：

- `autoSyncEnabled`
- `setDark()`
- `persist` 版本号
- `partialize()`：自动同步开启时不持久化任务派生 seedColor
- `migrate()`：升级时主动清掉旧任务主题，避免首页 hydrate 串色

### 5.3 主题色应用 Hook

当前 `useNovelTheme()` 是主题同步链的统一 choke point，不只是简单的 `seedColor -> palette` effect。

它还负责：

- 判断首页是否保持 neutral palette
- 判断小说详情页未选 task 时是否保持 neutral palette
- 查询任务状态，避免 pending/running task 过早请求 diagnosis
- 查询 diagnosis 的 `theme_color`
- `/dev/components` 试色页与业务路由隔离
- 当 diagnosis 缺失或非法时清掉旧任务 seed，避免业务页闪回默认紫色

### 5.4 使用流程

当前 live 流程：

1. 根据当前路由判断是否应保持 neutral palette
2. 若是任务页且 task 已稳定，再查询 `GET /diagnosis?task_id=...`
3. 若 `theme_color` 合法，则写入 `seedColor`
4. hook 生成 palette 并写回基础变量层
5. `globals.css` 的 `@theme inline` 让 Tailwind 和图表一起消费这些变量

## 六、ECharts 主题色对接

当前图表取色不是单一入口：

- `theme.ts` 里仍提供 `getCSSColorVar()` / `getEChartsColors()` / `getEmotionColors()`
- 但很多 live 图表会直接读取 `--primary`、`--chart-positive`、`--chart-negative`、`--chart-*`
- Topics 相关图表还共享 `CHART_COLORS` 的 8 槽位合同

因此当前图表配色真相应理解为：

1. CSS 变量是底层真相源
2. 各图表组件按自己的语义消费这些变量
3. 文档不应再假设所有图表都统一走单一 `echarts-theme.ts`

## 一、项目定位

### 1.1 产品目标

为中文网络小说量化分析系统构建面向**普通读者**的可视化展示前端，将后端分析结果以直观、美观、有动效的方式呈现，帮助读者理解小说的叙事结构、人物关系、情感走向等维度。

### 1.2 核心原则

| 原则 | 说明 |
|------|------|
| **读者友好** | 非技术用户也能直观理解所有可视化内容，避免专业术语堆砌 |
| **视觉优先** | 现代、优美、动画流畅，每一个交互都有反馈 |
| **一书一色** | 每本小说拥有独立的主题色，由后端诊断阶段生成，前端基于种子色派生完整色板 |
| **数据驱动** | 所有可视化内容来自后端 API，前端不做分析计算 |
| **渐进增强** | MVP 先覆盖核心可视化，后续迭代增加对比、导出等高级功能 |

### 1.3 用户画像

- **身份**: 普通读者、网文爱好者、书评人
- **技术水平**: 不需要技术背景
- **使用场景**: 浏览器中查看小说分析报告，理解一本书的叙事特点
- **无需登录**: 不涉及用户管理、权限控制

## 二、技术栈

### 2.1 核心框架

| 技术 | 版本 | 用途 |
|------|------|------|
| **React** | 18+ | UI 框架 |
| **TypeScript** | 5+ | 类型安全 |
| **Vite** | 5+ | 构建工具，开发体验优秀 |
| **React Router** | v6 | 客户端路由 |

### 2.2 UI 与样式

| 技术 | 用途 |
|------|------|
| **shadcn/ui** | 基础组件库（基于 Radix UI，CSS 变量驱动，完美适配动态主题色） |
| **TailwindCSS** | 原子化 CSS，配合 CSS 变量实现动态主题 |
| **Lucide React** | 图标库，与 shadcn/ui 配套 |

### 2.3 可视化

| 技术 | 用途 | 覆盖场景 |
|------|------|---------|
| **ECharts**（via `echarts-for-react`） | 主力图表库 | 折线图、柱状图、饼图、雷达图、词云、仪表盘 |
| **react-force-graph-2d** | 力导向图 | 人物关系知识图谱 |

### 2.4 动画

| 技术 | 用途 |
|------|------|
| **Framer Motion** | 页面转场、组件进场/退场、微交互、时间轴动画 |

| **Zustand** | 轻量客户端状态（主题色、深浅模式、当前选中的小说/任务） |

### 2.6 工程化

| 技术 | 用途 |
|------|------|

## 三、项目结构

### 3.1 仓库组织方式

采用 **Monorepo** 方案：前端代码作为现有后端仓库的 `frontend/` 子目录，共用一个 Git 仓库。

```
novel quantitative analysis/          # 项目根目录（现有仓库）
├── src/                              # 后端源码（不动）
├── docs/                             # 共享文档（不动）
├── config/                           # 后端配置（不动）
├── tests/                            # 后端测试（不动）
├── scripts/                          # 后端脚本（不动）
├── pyproject.toml                    # 后端依赖（不动）
├── ...
│
├── frontend/                         # ★ 前端项目（新增）
│   ├── public/
│   │   └── favicon.svg
│   ├── src/
│   │   └── ...                       # 前端源码（见下方详细结构）
│   ├── index.html
│   ├── package.json
│   ├── tailwind.config.ts
│   ├── tsconfig.json
│   ├── vite.config.ts
│   ├── Dockerfile
│   ├── nginx.conf
│   ├── .env
│   ├── .env.example
│   └── README.md
│
└── .gitignore                        # 需追加 Node 相关忽略规则
```

**Monorepo 优势**：
- 一个仓库、一套 Git 操作，无需管理多个仓库
- 前后端改动可在同一 commit 中关联（如后端加 `theme_color` 字段，前端同步对接）
- `docs/` 天然共享

**需追加到根目录 `.gitignore`**：
```gitignore
# Frontend
frontend/node_modules/
frontend/dist/
frontend/.env
frontend/.env.local
```

## 四、功能规划与迭代阶段

### Phase 1 · MVP（核心阅读体验）

目标：用户能上传小说、启动分析、查看核心分析结果。

| 优先级 | 功能模块 | 页面 | 对应 API |
|--------|---------|------|---------|
| P0 | 小说列表与上传 | `HomePage` | `GET /api/novels/`, `POST /api/novels/upload` |
| P0 | 分析启动与进度 | `HomePage` (内嵌) | `POST .../analyze`, `GET .../status` |
| P0 | 综合仪表盘 | `NovelDetailPage` | 五维 metrics + diagnosis |
| P0 | 情绪/节奏曲线 | `CurvesPage` | `GET .../chunk-curves` |
| P1 | 诊断报告 | `DiagnosisPage` | `GET .../diagnosis` |
| P1 | 角色分析 | `CharactersPage` | `GET .../characters` |

### Phase 2 · 深度可视化

目标：补全所有可视化维度，提供完整的分析报告体验。

| 优先级 | 功能模块 | 页面 | 对应 API |
|--------|---------|------|---------|
| P1 | 人物关系图谱 | `GraphPage` | `GET .../graph` |
| P1 | 叙事时间轴 | `TimelinePage` | `GET .../timeline` |
| P2 | 主题分布 | `TopicsPage` | `GET .../topics` |
| P2 | 任务历史管理 | `HomePage` (扩展) | `GET .../tasks`, `DELETE ...` |

### Phase 3 · 高级功能

目标：增强分析深度和横向对比能力。

| 优先级 | 功能模块 | 说明 |
|--------|---------|------|
| P3 | 多版本对比 | 同一小说不同分析版本的指标对比 |
| P3 | 多书籍对比 | 不同小说之间的维度雷达图对比 |
| P3 | 结果导出/分享 | 导出 PDF/图片、分享链接 |
| P3 | 响应式移动端 | 移动端布局适配 |

## 五、页面路由设计

```
/                           # 首页（小说列表 + 上传）
/novels/:novelId            # 小说详情/仪表盘（需选择 task）
/novels/:novelId/curves     # 情绪/节奏曲线
/novels/:novelId/characters # 角色分析
/novels/:novelId/graph      # 人物关系图谱
/novels/:novelId/topics     # 主题分布
/novels/:novelId/timeline   # 叙事时间轴
/novels/:novelId/diagnosis  # 诊断报告
```

**路由参数说明**：
- `novelId`: 小说 ID（后端返回的 8 位短 UUID）
- `task_id`: 通过 URL 查询参数或页面内选择器传递，不体现在路由路径中

## 六、设计规范

### 6.1 动态主题色系统

详见 [动态主题色系统设计文档](./前端-动态主题色系统设计.md)。

**核心理念**：后端在诊断阶段为每本小说返回一个种子色（`theme_color`），前端基于此色通过 HSL 运算派生完整色板，实现「一书一色」。

### 6.2 动画规范

| 场景 | 动画类型 | 时长 | 缓动函数 |
|------|---------|------|---------|
| 页面转场 | 淡入 + 微位移 | 300ms | `easeOut` |
| 卡片进场 | 交错淡入（stagger） | 150ms/项 | `easeOut` |
| 图表加载 | ECharts 内置动画 | 800ms | `cubicOut` |
| 数字变化 | 数字滚动动画 | 600ms | `easeInOut` |
| 悬浮反馈 | 微缩放 + 阴影 | 200ms | `easeOut` |
| 时间轴展开 | 展开 + 淡入 | 400ms | `spring` |

**Framer Motion 通用变体**：

```tsx
// 页面进场
const pageVariants = {
  initial: { opacity: 0, y: 20 },
  animate: { opacity: 1, y: 0, transition: { duration: 0.3 } },
  exit: { opacity: 0, y: -10, transition: { duration: 0.2 } },
};

// 列表交错进场
const staggerContainer = {
  animate: { transition: { staggerChildren: 0.08 } },
};

const staggerItem = {
  initial: { opacity: 0, y: 12 },
  animate: { opacity: 1, y: 0 },
};
```

### 6.3 响应式断点

| 断点名 | 宽度 | 布局 |
|--------|------|------|
| `sm` | ≥640px | 单列紧凑 |
| `md` | ≥768px | 双列 |
| `lg` | ≥1024px | 侧栏 + 内容区 |
| `xl` | ≥1280px | 宽屏仪表盘 |

MVP 阶段优先适配 `lg` 和 `xl`，移动端适配留到 Phase 3。

### 6.4 排版规范

| 元素 | 字号 | 字重 |
|------|------|------|
| 页面标题 | 2rem (32px) | 700 |
| 区块标题 | 1.25rem (20px) | 600 |
| 正文 | 1rem (16px) | 400 |
| 辅助文字 | 0.875rem (14px) | 400 |
| 数据标签 | 0.75rem (12px) | 500 |

中文字体栈：`"Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif`

## 七、开发规范

### 7.1 代码风格

- 使用 TypeScript 严格模式（`strict: true`）
- 组件使用函数式组件 + Hooks
- 文件命名：PascalCase（组件）、camelCase（工具/Hooks）
- 一个文件一个组件，组件文件名与导出名一致

### 7.2 Git 规范

- 分支策略：`main`（生产）→ `dev`（开发）→ `feature/*`（功能分支）
- Commit 格式：`type(scope): message`
  - `feat(frontend/charts): 添加情绪曲线组件`
  - `fix(frontend/theme): 修复深色模式下文字对比度`
  - `feat(api): diagnosis 接口新增 theme_color 字段`
  - `docs: 更新 API 对接文档`
- 前端相关 commit 的 scope 统一加 `frontend/` 前缀，便于区分前后端改动

### 7.3 目录约定

| 目录 | 职责 | 原则 |
|------|------|------|
| `api/` | 网络请求 | 只放 API 调用函数和类型定义，不含业务逻辑 |
| `components/` | 可复用组件 | 不直接调用 API，数据通过 props 传入 |
| `pages/` | 页面组件 | 负责数据获取（通过 hooks）和组件编排 |
| `hooks/` | 自定义 Hooks | 封装数据获取、状态逻辑等可复用逻辑 |
| `store/` | 全局状态 | 只存跨页面共享的状态，避免过度使用 |
| `lib/` | 纯函数工具 | 不依赖 React，可独立测试 |

## 八、部署方案

### 8.1 构建

```bash
cd frontend
npm run build    # 输出到 frontend/dist/ 目录
```

### 8.2 Nginx 部署

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /usr/share/nginx/html;
    index index.html;

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api/ {
        proxy_pass http://backend:8000/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 健康检查代理
    location /health {
        proxy_pass http://backend:8000/health;
    }

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

### 8.3 Docker 部署

```dockerfile
# frontend/Dockerfile
# 构建阶段
FROM node:20-alpine AS builder
WORKDIR /app
COPY frontend/package*.json ./
RUN npm ci
COPY frontend/ .
RUN npm run build

# 运行阶段
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
COPY frontend/nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

> **注意**：Dockerfile 的构建上下文（context）为项目根目录，因此 COPY 路径以 `frontend/` 开头。也可以将 context 设为 `frontend/` 目录，此时路径不需要前缀。

### 8.4 环境变量

| 变量名 | 说明 | 开发默认值 | 生产值 |
|--------|------|-----------|--------|
| `VITE_API_BASE_URL` | 后端 API 地址 | `http://localhost:8000` | 由 nginx 代理，使用相对路径 `/api` |

## 九、后端依赖说明

前端开发需要后端配合的改动：

| 改动项 | 说明 | 优先级 |
|--------|------|--------|
| `diagnosis` 接口新增 `theme_color` 字段 | 返回小说主题色（十六进制），由诊断阶段根据小说情感基调/类型自动生成 | P0（Phase 1 必需） |
| 无分析结果时的默认主题色 | 上传后未分析时使用后端返回的默认色或前端内置兜底色 | P0 |

CORS 已在后端全局配置（`allow_origins=["*"]`），无需额外修改。

## 一、数据库概述

### 1.1 数据库类型

项目使用 **PostgreSQL** 作为数据存储引擎，具有以下特点：
- 生产级关系型数据库，支持高并发
- 支持复杂查询和事务处理
- 启用外键约束确保数据完整性
- 通过 `run_id` 实现多任务数据隔离
- **pgvector 扩展**：支持向量相似度搜索

### 1.2 数据库连接配置

数据库连接通过 `DATABASE_URL` 环境变量配置：

```bash
# 使用 psycopg (v3) 驱动
DATABASE_URL=postgresql+psycopg://user:password@localhost:5432/novel_analysis
```

### 1.3 pgvector 扩展

项目使用 **pgvector** 扩展进行向量相似度搜索：

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 向量列定义（1536维，适用于 OpenAI text-embedding-3-small）
embedding_vector vector(1536)

-- 创建 HNSW 索引（高效的近似最近邻搜索）
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

### 1.4 ID 体系

| ID 类型 | 格式 | 示例 | 用途 | 使用场景 |
|---------|------|------|------|----------|
| run_id | 完整UUID(36位) | `10960c77-1a72-4444-a772-2ddc64334cd2` | 分析运行标识（核心隔离键） | 仅内部实现使用 |
| novel_id | UUID前8位 | `10960c77` | 小说唯一标识 | API内外通用 |
| task_id | UUID前8位 | `a1b2c3d4` | 分析任务标识（外部使用） | 仅API层使用 |
| chunk_id | 自增整数 | `1, 2, 3...` | 文本块标识 | 内部使用 |
| entity_id | 自增整数 | `1, 2, 3...` | 实体标识 | 内部使用 |

**ID映射关系：**
- `task_id` 是 `run_id` 的前8位字符
- 外部API只暴露 `task_id`，完全隐藏 `run_id`
- 内部实现（Repository、Workflow）只使用 `run_id`
- ID转换由API层和Service层负责

### 1.5 数据隔离策略

所有业务表通过 `run_id` 外键关联 `analysis_runs` 表实现数据隔离：

```sql
-- analysis_runs 表结构
CREATE TABLE analysis_runs (
    run_id VARCHAR(36) PRIMARY KEY,
    novel_id VARCHAR(36) NOT NULL,
    status VARCHAR(20) DEFAULT 'running',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    completed_at TIMESTAMP,
    source_path TEXT,
    novel_title TEXT
);

-- 所有业务表添加 run_id 外键
ALTER TABLE chunks ADD COLUMN run_id VARCHAR(36) REFERENCES analysis_runs(run_id) ON DELETE CASCADE;
```

## 二、数据库连接配置

```python
# 创建时间: 2026-03-15
# 创建者: TraeAI
# 任务: postgresql-migration
# 说明: SQLAlchemy 数据库连接配置

from sqlalchemy import create_engine
from sqlalchemy.orm import sessionmaker
import os

DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+psycopg://postgres:postgres@localhost:5432/novel_analysis")

engine = create_engine(DATABASE_URL, pool_size=5, max_overflow=10)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

def get_session():
    """获取数据库会话"""
    session = SessionLocal()
    try:
        yield session
    finally:
        session.close()
```

**唯一约束**: (graph_name, run_id)

---

#### 3.5.5 disambig_checkpoint - 消歧检查点表

存储人名消歧过程中的检查点数据，用于断点恢复。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| run_id | VARCHAR(36) | PRIMARY KEY | 运行ID（主键，外键关联 analysis_runs） |
| alias_map | TEXT | NOT NULL | 别名映射表（JSON格式） |
| updated_at | REAL | NOT NULL | 更新时间戳 |

**外键**: run_id → analysis_runs(run_id) ON DELETE CASCADE

**说明**：
- `alias_map` 存储内存中的别名映射，格式为 `{"别名": "正式名"}` 的 JSON 对象
- 增量消解过程中每隔 N 块保存一次，确保任务中断后可恢复
- 最终消解完成后，数据被 `apply_alias_corrections` 批量写入各标注表

## 四、向量搜索

### 4.1 pgvector 使用

```python
from sqlalchemy import select
from src.storage.models import Entity, ChunkEmbedding

# 余弦相似度搜索
query_vector = [0.1, 0.2, ...]  # 1536维向量

stmt = select(Entity).order_by(
    Entity.embedding_vector.cosine_distance(query_vector)
).limit(10)

# L2 距离搜索
stmt = select(ChunkEmbedding).order_by(
    ChunkEmbedding.embedding_vector.l2_distance(query_vector)
).limit(10)
```

### 4.2 向量索引

使用 HNSW（Hierarchical Navigable Small World）索引进行高效的近似最近邻搜索：

```sql
-- 创建索引
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 查询时设置 ef 参数（影响搜索精度）
SET hnsw.ef_search = 100;
```

## 六、数据流说明

### 6.1 预处理阶段（preprocess）

1. **文本读取** → `chunks` 表
2. **语言风格计算** → `chunk_style` 表
3. **传统文化计算** → `chunk_culture` 表

### 6.2 标注阶段（annotate）

1. **本地模型标注** → `chunk_annotation` 表
2. **人物提取** → `chunk_characters` 表
3. **关系提取** → `chunk_relations` 表
4. **对话提取** → `chunk_dialogues` 表
5. **人名消歧** → `entities`, `entity_aliases` 表
6. **消歧检查点** → `disambig_checkpoint` 表（增量保存）
7. **上下文更新** → `global_context`, `entity_registry` 表
8. **身份线索记录** → `character_appearances` 表

### 6.3 聚合阶段（aggregate）

1. **情感曲线计算** → `emotion_curve` 表
2. **节奏曲线计算** → `rhythm_curve` 表
3. **全局统计计算** → `global_stats` 表
4. **人物关系图构建** → `graph_storage` 表

### 6.4 主题建模阶段（topic-model）

1. **LDA主题提取** → `chunk_topics` 表

### 6.5 诊断阶段（diagnose）

1. **云端模型诊断** → `cloud_analysis` 表

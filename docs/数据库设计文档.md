# 数据库设计文档

---

## 一、数据库概述

### 1.1 数据库类型

项目使用 **PostgreSQL** 作为数据存储引擎，具有以下特点：
- 生产级关系型数据库，支持高并发
- 支持复杂查询和事务处理
- 启用外键约束确保数据完整性
- 通过 `run_id` 实现多任务数据隔离
- **pgvector 扩展**：支持向量相似度搜索

### 1.2 数据库连接配置

数据库连接支持"基础地址 + 独立账号密码"两段式配置：

```bash
# 使用 psycopg (v3) 驱动
DATABASE_URL=postgresql+psycopg://localhost:5432/novel_analysis
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=your_password
```

### 1.3 pgvector 扩展

项目使用 **pgvector** 扩展进行向量相似度搜索：

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 向量列定义（维度由配置 settings.models.semantic_chunking.embedding_dim 决定，默认 1024）
embedding_vector vector(1024)

-- 创建 HNSW 索引（高效的近似最近邻搜索）
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

### 1.4 ID 体系

| ID 类型 | 格式 | 示例 | 用途 | 使用场景 |
|---------|------|------|------|----------|
| run_id | 完整UUID(36位) | `10960c77-1a72-4444-a772-2ddc64334cd2` | 分析运行标识（核心隔离键） | 仅内部实现使用 |
| novel_id | UUID前8位 | `10960c77` | 小说唯一标识 | API内外通用 |
| task_id | UUID前8位 | `a1b2c3d4` | 分析任务标识（外部使用） | 仅API层使用 |
| chunk_id | 自增整数 | `1, 2, 3...` | 文本块标识 | 内部使用 |
| entity_id | 自增整数 | `1, 2, 3...` | 实体标识 | 内部使用 |

**ID映射关系：**
- `task_id` 是 `run_id` 的前8位字符
- 外部API只暴露 `task_id`，完全隐藏 `run_id`
- 内部实现（Repository、Workflow）只使用 `run_id`
- ID转换由API层和Service层负责

### 1.5 数据隔离策略

所有业务表通过 `run_id` 外键关联 `analysis_runs` 表实现数据隔离。绝大多数 chunk 级表使用 `(chunk_id, run_id)` 复合主键 + 复合外键引用 `chunks` 表，确保同一 chunk 在不同 run 下的数据互不干扰。

## 二、数据库连接配置

项目通过分离式环境变量 + 三层封装管理数据库连接，实际代码位于 `src/storage/` 目录下。

### 2.1 环境变量配置

基础连接地址与账号密码分离存放：

```bash
# .env / .env.example
DATABASE_URL=postgresql+psycopg://localhost:5432/novel_analysis
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=your_password
```

连接池参数可通过环境变量按需覆盖（默认值由 `db.py` 内置）：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `DB_POOL_SIZE` | 5 | 连接池大小 |
| `DB_MAX_OVERFLOW` | 10 | 最大溢出连接数 |
| `DB_POOL_TIMEOUT` | 30 | 获取连接超时（秒） |
| `DB_POOL_RECYCLE` | 3600 | 连接回收时间（秒） |

### 2.2 连接链路

```
.env 环境变量
  → database_url.py: resolve_database_url_from_env() 合并凭证到 URL
    → db.py: get_engine()       单例 create_engine (QueuePool)
      → db.py: get_session_factory()  单例 sessionmaker
        → db.py: get_session()        上下文管理器（自动 commit/rollback/close）
        → session.py: DatabaseSession / SessionFactory  高级封装层
```

核心获取会话的方式：

```python
from src.storage.db import get_session

with get_session() as session:
    # 自动 commit，异常时 rollback
    novel = session.query(Novel).filter_by(novel_id="xxx").first()
```

## 三、表结构详解

### 3.1 核心数据表

#### 3.1.1 chunks - 文本块表

存储分块后的文本数据。使用复合主键 `(chunk_id, run_id)` 支持多 run 数据隔离。

| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| chunk_id | INTEGER | PRIMARY KEY | 块ID |
| chapter_id | INTEGER | nullable | 章节ID |
| char_offset | INTEGER | nullable | 块文本在全文中的起始字符偏移 |
| char_end_offset | INTEGER | nullable | 块文本在全文中的结束字符偏移 |
| text | TEXT | NOT NULL | 块文本内容 |
| run_id | VARCHAR(36) | PRIMARY KEY, FK | 运行ID（复合主键，外键关联 analysis_runs，ON DELETE CASCADE） |

**索引**: idx_chunks_run_id (run_id)

#### 3.1.5 chunk_relations - 人物关系表

存储每个文本块中的人物关系变化（Phase4 输出）。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | INTEGER | 记录ID（主键，自增） |
| chunk_id | INTEGER | 块ID |
| from_char | VARCHAR(255) | 关系发起方（原始称呼） |
| to_char | VARCHAR(255) | 关系接收方（原始称呼） |
| from_reference_kind | VARCHAR(50) | 发起方引用类型 |
| to_reference_kind | VARCHAR(50) | 接收方引用类型 |
| resolved_from_global_name | VARCHAR(255) | 发起方消歧后全局规范名 |
| resolved_to_global_name | VARCHAR(255) | 接收方消歧后全局规范名 |
| reference_skip_reason | TEXT | 跳过引用消歧的原因 |
| type | VARCHAR(50) | 关系类型：师徒/敌对/盟友/爱慕/家族/利益/主从 |
| change | VARCHAR(50) | 关系变化：强化/弱化/新建/断裂/无变化 |
| directionality | VARCHAR(20) | 关系方向性（如 directed / symmetric） |
| evidence | TEXT | 原文证据片段 |
| confidence | REAL | Phase4 抽取置信度 |
| source_model | VARCHAR(100) | 模型来源 |
| projection_status | VARCHAR(20) | 图谱投影状态（pending / projected / failed） |
| projected_at | TIMESTAMP | 最近一次投影时间 |
| projection_error | TEXT | 投影失败原因 |
| run_id | VARCHAR(36) | 运行ID（外键） |

**外键**: (chunk_id, run_id) → chunks(chunk_id, run_id) ON DELETE CASCADE, run_id → analysis_runs(run_id) ON DELETE CASCADE
**索引**: idx_chunk_relations_chunk_id (chunk_id), idx_chunk_relations_run_id (run_id), idx_chunk_relations_projection_status (run_id, projection_status)

**设计说明**：
- `from_char` / `to_char` 保存原始称呼，Phase4 面向原文，是证据提取阶段
- 正式名归一化由图谱投影阶段处理，结果写入 graph_relation_events
- `evidence` 字段支持证据追溯，每条关系都能追溯到原文
- 投影链路通过 `projection_status` / `projected_at` / `projection_error` 追踪

## 四、向量搜索

### 4.1 pgvector 使用

```python
from sqlalchemy import select
from src.storage.models import ChunkEmbedding

# 余弦相似度搜索
query_vector = [0.1, 0.2, ...]  # 向量维度由配置决定，默认 1024

# L2 距离搜索
stmt = select(ChunkEmbedding).order_by(
    ChunkEmbedding.embedding_vector.l2_distance(query_vector)
).limit(10)
```

### 4.2 向量索引

使用 HNSW（Hierarchical Navigable Small World）索引进行高效的近似最近邻搜索：

```sql
-- 创建索引
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 查询时设置 ef 参数（影响搜索精度）
SET hnsw.ef_search = 100;
```

## 五、当前表关系概览

- `novels`

  - 被 `model_interactions`、`foreshadowing_thread_hits`、`graph_relation_events` 通过复合外键引用。

  - 汇总诊断输出；`global_stats` / `stage_summaries` / `chunk_curves` / `foreshadowing_threads` 为其上游支撑数据。

## 六、数据流说明

### 6.1 预处理阶段（preprocess）

1. **文本读取** → `chunks` 表
2. **语言风格计算** → `chunk_style` 表
3. **传统文化计算（chunk级命中）** → `chunk_style.imagery_lexicon_density`

### 6.2 标注阶段（annotate）

1. **本地模型标注** → `chunk_annotation` 表
2. **人物提取** → `chunk_characters` 表
3. **关系提取** → `chunk_relations` 表
4. **对话提取** → `chunk_dialogues` 表
5. **伏笔与地点抽取** → `chunk_foreshadowing`, `chunk_locations` 表
6. **身份线索记录** → `character_appearances` 表
7. **消歧检查点** → `disambig_checkpoint` 表（增量保存）
8. **setup thread 同步** → `foreshadowing_threads`, `foreshadowing_thread_hits` 表
9. **图谱权威投影** → `graph_entities`, `graph_entity_aliases`, `graph_relation_events`, `graph_relations_current`, `graph_entity_participants` 表
10. **上下文更新** → `global_context` 表

### 6.3 聚合阶段（aggregate）

1. **情感/节奏曲线计算** → `chunk_curves` 表
2. **全局统计计算** → `global_stats` 表
3. **阶段性摘要收口** → `stage_summaries` 表

### 6.4 主题建模阶段（topic-model）

1. **LDA主题提取** → `chunk_topics` 表

### 6.5 诊断阶段（diagnose）

## 八、数据完整性约束

### 8.1 外键约束

所有外键约束已启用，确保：
- 无法删除被引用的父记录
- 无法插入不存在的外键值
- 级联删除：`ON DELETE CASCADE`（chunk 级表）

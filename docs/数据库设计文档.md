## 一、数据库概述

### 1.1 数据库类型

项目使用 **PostgreSQL** 作为数据存储引擎，具有以下特点：
- 生产级关系型数据库，支持高并发
- 支持复杂查询和事务处理
- 启用外键约束确保数据完整性
- 通过 `run_id` 实现多任务数据隔离
- **pgvector 扩展**：支持向量相似度搜索

### 1.2 数据库连接配置

数据库连接支持“基础地址 + 独立账号密码”两段式配置：

```bash
# 使用 psycopg (v3) 驱动
DATABASE_URL=postgresql+psycopg://localhost:5432/novel_analysis
DATABASE_USERNAME=postgres
DATABASE_PASSWORD=your_password
```

### 1.3 pgvector 扩展

项目使用 **pgvector** 扩展进行向量相似度搜索：

```sql
-- 启用扩展
CREATE EXTENSION IF NOT EXISTS vector;

-- 向量列定义（1536维，适用于 OpenAI text-embedding-3-small）
embedding_vector vector(1536)

-- 创建 HNSW 索引（高效的近似最近邻搜索）
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);
```

### 1.4 ID 体系

| ID 类型 | 格式 | 示例 | 用途 | 使用场景 |
|---------|------|------|------|----------|
| run_id | 完整UUID(36位) | `10960c77-1a72-4444-a772-2ddc64334cd2` | 分析运行标识（核心隔离键） | 仅内部实现使用 |
| novel_id | UUID前8位 | `10960c77` | 小说唯一标识 | API内外通用 |
| task_id | UUID前8位 | `a1b2c3d4` | 分析任务标识（外部使用） | 仅API层使用 |
| chunk_id | 自增整数 | `1, 2, 3...` | 文本块标识 | 内部使用 |
| entity_id | 自增整数 | `1, 2, 3...` | 实体标识 | 内部使用 |

**ID映射关系：**
- `task_id` 是 `run_id` 的前8位字符
- 外部API只暴露 `task_id`，完全隐藏 `run_id`
- 内部实现（Repository、Workflow）只使用 `run_id`
- ID转换由API层和Service层负责

### 1.5 数据隔离策略

所有业务表通过 `run_id` 外键关联 `analysis_runs` 表实现数据隔离：

```sql
-- analysis_runs 表结构
CREATE TABLE analysis_runs (
    run_id VARCHAR(36) PRIMARY KEY,
    novel_id VARCHAR(255) NOT NULL REFERENCES novels(novel_id) ON DELETE RESTRICT,
    source_path TEXT,
    title VARCHAR(500),
    author VARCHAR(255),
    status VARCHAR(50) NOT NULL DEFAULT 'pending',
    progress REAL NOT NULL DEFAULT 0.0,
    stage VARCHAR(255),
    sub_stage VARCHAR(255),
    current INTEGER NOT NULL DEFAULT 0,
    total INTEGER NOT NULL DEFAULT 100,
    message TEXT,
    error TEXT,
    task_kind VARCHAR(50) NOT NULL DEFAULT 'analysis',
    request_payload TEXT,
    cancel_requested BOOLEAN NOT NULL DEFAULT FALSE,
    worker_id VARCHAR(255),
    heartbeat_at TIMESTAMP,
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    created_at TIMESTAMP,
    updated_at TIMESTAMP
);

-- 所有业务表添加 run_id 外键
ALTER TABLE chunks ADD COLUMN run_id VARCHAR(36) REFERENCES analysis_runs(run_id) ON DELETE CASCADE;
```

```python
# 创建时间: 2026-03-15

# 任务: postgresql-migration
# 说明: SQLAlchemy 数据库连接配置

from sqlalchemy import create_engine

import os

DATABASE_URL = os.getenv("DATABASE_URL", "postgresql+psycopg://localhost:5432/novel_analysis")
DATABASE_USERNAME = os.getenv("DATABASE_USERNAME", "postgres")
DATABASE_PASSWORD = os.getenv("DATABASE_PASSWORD", "postgres")

engine = create_engine(
    f"postgresql+psycopg://{DATABASE_USERNAME}:{DATABASE_PASSWORD}@localhost:5432/novel_analysis",
    pool_size=5,
    max_overflow=10,
)
SessionLocal = sessionmaker(autocommit=False, autoflush=False, bind=engine)

def get_session():
    """获取数据库会话"""
    session = SessionLocal()
    try:
        yield session
    finally:
        session.close()
```

#### 3.1.5 chunk_relations - 人物关系表

存储每个文本块中的人物关系变化（Phase4 输出）。

| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | INTEGER | 记录ID（主键，自增） |
| chunk_id | INTEGER | 块ID（外键关联chunks） |
| from_char | TEXT | 关系发起方（原始称呼） |
| to_char | TEXT | 关系接收方（原始称呼） |

| change | TEXT | 关系变化：强化/弱化/新建/断裂/无变化 |

| evidence | TEXT | 原文证据片段（v10.6 新增） |
| confidence | REAL | Phase4 抽取置信度（v10.6 新增） |

| projected_at | TIMESTAMP | 最近一次投影时间 |
| projection_error | TEXT | 投影失败原因 |
| run_id | VARCHAR(36) | 运行ID（外键） |

**外键**: chunk_id → chunks(chunk_id), run_id → analysis_runs(run_id)
**索引**: idx_chunk_relations_chunk (chunk_id), idx_chunk_relations_run_id (run_id), idx_chunk_relations_projection_status (run_id, projection_status)

**设计说明（v10.6）**：
- `from_char` / `to_char` 保存原始称呼，Phase4 面向原文，是证据提取阶段
- 正式名归一化由图谱投影阶段处理，结果写入 graph_relation_events
- `evidence` 字段支持证据追溯，每条关系都能追溯到原文
- 投影链路当前通过 `projection_status` / `projected_at` / `projection_error` 追踪，而不再使用旧 `normalized` 布尔列

## 四、向量搜索

### 4.1 pgvector 使用

```python
from sqlalchemy import select
from src.storage.models import Entity, ChunkEmbedding

# 余弦相似度搜索
query_vector = [0.1, 0.2, ...]  # 1536维向量

stmt = select(Entity).order_by(
    Entity.embedding_vector.cosine_distance(query_vector)
).limit(10)

# L2 距离搜索
stmt = select(ChunkEmbedding).order_by(
    ChunkEmbedding.embedding_vector.l2_distance(query_vector)
).limit(10)
```

### 4.2 向量索引

使用 HNSW（Hierarchical Navigable Small World）索引进行高效的近似最近邻搜索：

```sql
-- 创建索引
CREATE INDEX idx_chunk_embeddings_vector 
ON chunk_embeddings 
USING hnsw (embedding_vector vector_cosine_ops)
WITH (m = 16, ef_construction = 64);

-- 查询时设置 ef 参数（影响搜索精度）
SET hnsw.ef_search = 100;
```

## 六、数据流说明

### 6.1 预处理阶段（preprocess）

1. **文本读取** → `chunks` 表
2. **语言风格计算** → `chunk_style` 表
3. **传统文化计算（chunk级命中）** → `chunk_style.imagery_lexicon_density`

### 6.2 标注阶段（annotate）

1. **本地模型标注** → `chunk_annotation` 表
2. **人物提取** → `chunk_characters` 表
3. **关系提取** → `chunk_relations` 表
4. **对话提取** → `chunk_dialogues` 表
5. **伏笔与地点抽取** → `chunk_foreshadowing`, `chunk_locations` 表
6. **身份线索记录** → `character_appearances` 表
7. **消歧检查点** → `disambig_checkpoint` 表（增量保存）
8. **setup thread 同步** → `foreshadowing_threads`, `foreshadowing_thread_hits` 表
9. **图谱权威投影** → `graph_entities`, `graph_entity_aliases`, `graph_relation_events`, `graph_relations_current`, `graph_entity_participants` 表
10. **上下文更新** → `global_context` 表

### 6.3 聚合阶段（aggregate）

1. **情感/节奏曲线计算** → `chunk_curves` 表
2. **全局统计计算** → `global_stats` 表
3. **阶段性摘要收口** → `stage_summaries` 表

### 6.4 主题建模阶段（topic-model）

1. **LDA主题提取** → `chunk_topics` 表

### 6.5 诊断阶段（diagnose）

1. **读取全局统计 / 阶段摘要 / 伏笔线程 / 主题信息** → 诊断 payload
2. **云端模型诊断** → `cloud_analysis` 表
